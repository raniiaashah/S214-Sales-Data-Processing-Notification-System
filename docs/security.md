# S214 Sales Platform - Security Documentation

## Security Overview

This document describes the security measures implemented in the S214 Sales Platform.

## Security Measures

### Network Security

#### VPC Design
- **Public Subnets**: Only for NAT Gateway
- **Private Subnets**: For RDS and Lambda
- **No Public RDS**: Database is not accessible from the internet
- **VPC Flow Logs**: All network traffic is logged

#### Security Groups
- **RDS Security Group**: Allows MySQL (3306) only from Lambda security group
- **Lambda Security Group**: Allows outbound to RDS and HTTPS to AWS services
- **No Broad CIDR**: Uses security group references instead of CIDR blocks

#### VPC Endpoints
- **S3 Endpoint**: Gateway endpoint (free) for S3 access
- **Secrets Manager Endpoint**: Interface endpoint for Secrets Manager
- **SNS Endpoint**: Interface endpoint for SNS
- **CloudWatch Logs Endpoint**: Interface endpoint for CloudWatch

### Data Security

#### Encryption at Rest
- **RDS**: Storage encryption enabled
- **Secrets Manager**: Encrypted with AWS managed key
- **SNS**: Encrypted with KMS key
- **CloudWatch Logs**: Encrypted with AWS managed key

#### Encryption in Transit
- **TLS**: All connections use TLS
- **RDS**: MySQL connections use SSL
- **API Calls**: All AWS API calls use HTTPS

### Secrets Management

#### AWS Secrets Manager
- **Database Credentials**: Username and password stored in Secrets Manager
- **Auto-Generation**: Password is auto-generated by Secrets Manager
- **No Hardcoded Secrets**: No passwords in code or templates
- **Runtime Retrieval**: Lambda retrieves credentials at runtime

#### SSM Parameter Store
- **Non-Sensitive Only**: Only resource identifiers stored
- **No Passwords**: Passwords are never stored in SSM
- **Hierarchical**: Parameters organized by environment

### IAM Security

#### Least Privilege
- **Dedicated Roles**: Each Lambda has its own IAM role
- **Minimal Permissions**: Only required permissions granted
- **No Wildcards**: No use of `*` in resource ARNs
- **No AdministratorAccess**: No broad permissions

#### Processor Lambda Permissions
- **CloudWatch Logs**: Write logs only
- **Secrets Manager**: Read only specific secret
- **SNS**: Publish only to specific topic
- **KMS**: Decrypt only for Secrets Manager

#### Custom Resource Lambda Permissions
- **CloudWatch Logs**: Write logs only
- **Secrets Manager**: Read only specific secret
- **KMS**: Decrypt only for Secrets Manager

### Security Scanning

#### Bandit
- **Purpose**: Static analysis of Python code for security issues
- **Checks**: SQL injection, command injection, hardcoded passwords
- **Configuration**: Runs in CI pipeline

#### pip-audit
- **Purpose**: Check Python dependencies for known vulnerabilities
- **Checks**: CVE database for vulnerable packages
- **Configuration**: Runs in CI pipeline

#### cfn-lint
- **Purpose**: Validate CloudFormation templates for security issues
- **Checks**: IAM policies, security groups, encryption
- **Configuration**: Runs in CI pipeline

#### Checkov
- **Purpose**: Comprehensive IaC security scanning
- **Checks**: CIS benchmarks, best practices
- **Configuration**: Runs in CI pipeline

#### GitLeaks
- **Purpose**: Detect secrets in source code
- **Checks**: API keys, passwords, tokens
- **Configuration**: Runs in CI pipeline

## Security Best Practices

### Code Quality
- **Input Validation**: All inputs are validated
- **Parameterized Queries**: SQL queries use parameters
- **Error Handling**: Errors are handled gracefully
- **No Sensitive Logging**: Credentials are never logged

### Infrastructure
- **Immutable Infrastructure**: Infrastructure is replaced, not modified
- **Version Control**: All templates stored in Git
- **Change Tracking**: All changes are tracked and auditable
- **Automated Deployment**: No manual console changes

### Monitoring
- **CloudWatch Logs**: All Lambda invocations are logged
- **CloudWatch Alarms**: Alarms for errors and duration
- **VPC Flow Logs**: Network traffic is logged
- **CloudTrail**: AWS API calls are logged

## Compliance Considerations

### Data Protection
- **Encryption**: All sensitive data is encrypted
- **Access Control**: Least privilege access
- **Audit Trail**: All access is logged
- **Data Residency**: Data stays in specified region

### Network Security
- **Segmentation**: Public/private subnet separation
- **Firewall**: Security groups control traffic
- **Monitoring**: VPC flow logs capture traffic
- **Endpoints**: VPC endpoints reduce internet exposure

## Security Checklist

Before deploying to production:

- [ ] All secrets stored in Secrets Manager
- [ ] No hardcoded credentials in code
- [ ] Security groups use least privilege
- [ ] IAM roles have minimal permissions
- [ ] Encryption at rest is enabled
- [ ] Encryption in transit is enforced
- [ ] VPC flow logs are enabled
- [ ] CloudWatch alarms are configured
- [ ] Security scanning passes in CI
- [ ] No secrets detected in code

## Incident Response

### Detection
- **CloudWatch Alarms**: Notify on errors
- **VPC Flow Logs**: Detect unusual traffic
- **CloudTrail**: Detect unauthorized API calls

### Response
1. Identify the issue
2. Isolate affected resources
3. Investigate root cause
4. Apply fixes
5. Verify resolution

### Recovery
1. Restore from backups if needed
2. Redeploy infrastructure if needed
3. Rotate credentials if compromised
4. Update security measures
